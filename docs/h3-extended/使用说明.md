# MiniMax H3 使用说明（直白版）

这份说明对应本机 AIGC 工作台里的 **15 个 H3 扩展模板**，也补充介绍列表最前面的 **2 个基础视频模板**。名字与界面一致，括号里的 `h3-xxx` 是模板编号，方便对照文件。

你在本机上传图片、录音或视频，DGX 负责生成，工作台把结果下载到本机。**先用默认参数生成一条短片，再慢慢改效果。** 不需要先弄懂画布里的全部方框。

截至 2026-10-31，15 个扩展模板都已有成功生成并保存的记录。大多数样片约 5 秒，两段续镜约 9.42 秒。这说明流程能运行；换一套素材后，人物是否像、动作是否自然、嘴型是否合拍，仍要自己看成片。

## 所有模板都这样开始

1. 双击项目里的 `start.cmd`，或打开 [AIGC 工作台](http://127.0.0.1:8766/)。如果网页打不开，先运行 `start.cmd`。
2. 选择 **MiniMax H3 · 视频**，找到要用的模板，点击 **一键打开**。这个按钮会在需要时连接 DGX、启动生成环境并加载模板。
3. 等页面提示模板已加载。页面里的 **ComfyUI** 是生成视频的操作界面；里面的方框叫 **节点**，每个方框负责一件事，比如读图、生成或保存。
4. 在下面提到的上传方框中选择你自己的文件。模板里的 `reference.png`、`source.mp4` 等只是预设名字，**不能当作已经上传好的素材**。
5. 找到 `prompt`，改成你想要的动作或画面。`prompt` 就是**提示词：告诉模型要生成什么的一段文字**。第一次可以保留模板现有文字，只换素材。
6. 检查上传框已经显示你选的文件，再点击 ComfyUI 的 **运行** 按钮。若界面显示英文，`Run` 或 `Queue Prompt` 也是提交生成的意思。
7. 等工作台显示结果已保存，再到 [本地作品库](http://127.0.0.1:8766/library)看视频、听声音、下载文件。

**一键打开只是加载模板，还需要你手动点击运行。** 一次先提交一条，方便知道每次修改带来了什么变化。

### 画布里主要找这几个方框

| 方框名称或字段 | 你要做什么 |
|---|---|
| `LoadImage` | 上传图片；一般先用 PNG 或 JPG |
| `LoadAudio` | 上传录音；第一次建议用 WAV，也就是常见的音频文件格式 |
| `VHS_LoadVideo`，标题可能显示 Load Video | 上传原视频；第一次建议用普通 MP4 |
| `MiniMaxH3ImageToVideo` 或 `MiniMaxH3ReferenceToVideo` | 找里面的 `prompt`、`width`、`height`、`length`；它们分别是描述、宽、高、画面张数 |
| `AIGCLoadH3Reference` | 点击 **上传参考素材**，选择保存的人物参考文件 |
| `SaveVideo` | 负责保存视频，第一次保持默认即可 |

如果画布中有多个读图或读视频方框，按下面每个模板的用途确认它们分别接收什么素材。

### 第一次先别改这些

扩展模板大多默认宽 `512`、高 `320`、`length` 为 `124`、`steps` 为 `4`。两个基础模板的默认值有所不同，直接沿用各自默认值即可。

| 参数 | 直白解释 | 使用建议 |
|---|---|---|
| `width` / `height` | 视频的宽和高，单位是像素；像素就是组成画面的小点 | 扩展模板先用 512×320。要改尺寸，宽高都用 32 的整数倍 |
| `length` | 视频里有多少张画面，也叫多少帧 | 默认 124 帧约 5.17 秒。帧就是视频中的一张画面 |
| `fps` / `force_rate` | 每秒播放或读取多少张画面 | 模板用 24，表示每秒 24 张。先别改，否则时长和声音可能对不上 |
| `steps` | 模型分几次把画面逐步生成出来，也叫采样步数 | 扩展模板配的是 4 步加速方案。步数加大不一定更好，先保持默认 |
| `noise_seed` / `seed` | 随机种子，可以理解成决定随机变化的号码 | 比较两个参数时固定同一个号码；想试另一种结果再换号码 |
| `denoise` | 重新绘制的幅度；越大，通常越容易改动原画面 | 做修脸或细节增强时，先用模板值，别一开始拉满 |
| `strength` / `strength_model` | 某个参考或附加模型影响结果的力度 | 不同方框的强度控制不同东西，按下文对应项调整 |

H3 的画面张数有固定间隔，不是随便填一个数字都合适。例如 `39` 帧约 1.63 秒，`73` 帧约 3.04 秒，`124` 帧约 5.17 秒。第一次用默认值；不要只改保存方框里的播放速度来增加时长。

遇到 `<Picture 1>`、`<Video 1>`、`<Audio 1>`，它们分别是**第 1 张参考图、第 1 个参考视频、第 1 段参考声音**的标记，不是文件名。初次使用保留模板里的这些标记，以及下文提到的特殊前缀。

## 1. LightX2V 首帧视频（h3-lightx）

**做什么：** 让一张静止图片动起来。例如让照片中的人转头、微笑，或者让风景里的镜头慢慢往前走。首帧就是视频开头的第一张画面。

**准备：** 一张清楚的图片。

**怎么用：** 打开模板 → 在 `LoadImage` 上传图片 → 在 `prompt` 描述动作和镜头 → 保持默认参数运行。

**可以这样描述：** 人物慢慢转头看向镜头，轻轻微笑，镜头保持不动，背景不变。

**注意：** LightX2V 是这个模板使用的加速方案名称，你不用单独操作它。先做一个简单动作；一次要求跑步、转身、换景、镜头环绕，容易乱。声音由模型生成，未必会严格满足“安静”或“无音乐”的描述。

## 2. 两段连续镜头（h3-continuation）

**做什么：** 自动生成第一段，再利用第一段末尾的信息继续生成第二段，最后合成一个视频。

**准备：** 一张人物或场景图。

**怎么用：** 打开模板 → 上传图片 → 修改 `prompt`，描述一个可以持续的场景或动作 → 运行。当前模板两段使用相同描述，先不用改连线。

**可以这样描述：** 同一个人在公园里缓慢行走，镜头平稳跟随，人物外貌、衣服和光线保持一致。

**注意：** 两段之间会保留一小段共同画面，再拼接起来，帮助连接更顺。这个共同部分叫**重叠帧**；默认重叠 22 帧。两段各 124 帧，合起来约 9.42 秒，默认一次生成两段。

这不是上传任意 MP4 后自动接着拍，也没有配好无限循环。想接更多段，需要扩展流程。验收时重点看中间接缝有没有跳脸、换衣服、突然变光，声音有没有突变。

## 3. 录音驱动数字人（h3-digital-human）

**做什么：** 让图片里的人根据你上传的录音说话。这里的数字人就是**由模型生成的、会说话的人物视频**。

**准备：** 一张正面或稍微侧面的清楚人物图，加一段干净录音。建议先用 3～5 秒的一人说话录音。

**怎么用：** 打开模板 → 在 `LoadImage` 上传人物图 → 在 `LoadAudio` 上传录音 → 先保留现有说话描述 → 运行。

**注意：** 台词来自录音，修改提示词不会把录音里的话换掉。想换台词，先换一段录音；也可以先用 VoxCPM2 把文字生成语音，再把音频文件上传到这里。

视频时长会跟随录音，并稍作对齐；末尾可能补一点静音。默认最多约 5.17 秒，超过的录音会被截取。长录音第一次先分成短段，不要以为整段都会被用上。生成的成片使用对应输入音轨，但人物嘴巴是否与发音合拍仍要看视频。

## 4. 提取人声并驱动数字人（h3-vocal-human）

**做什么：** 录音里有伴奏或背景音乐时，先尽量分离出说话声或歌声，再用这段人声生成数字人。

**准备：** 一张人物图，加一段带音乐的人声录音。

**怎么用：** 打开模板 → 上传人物图和录音 → 保持模板里提取人声的方框连接不动 → 运行。

**注意：** 成片使用**分离后的人声**，不会自动把原伴奏加回去。分离可能留下音乐残音，也可能让人声变薄、变闷；先听生成结果。如果你的录音本来就只有清楚人声，直接用上一项即可。

这一步用的 MelBandRoFormer 是**把人声和伴奏分开的模型名称**，不是需要你填写的参数。唱歌时嘴型和表情仍要单独检查。

## 5. 动作迁移与人物替换（h3-character-swap）

**做什么：** 参考原视频里的动作、表情和镜头，让另一个人来演。动作迁移就是**让新人物模仿原视频的动作**。

**准备：** 一段只有一个主要人物的短视频，加一张新人物的清楚图片。想换服装，就让参考图清楚显示那套服装。

**怎么用：** 打开模板 → 在 `VHS_LoadVideo` 上传原视频 → 在 `LoadImage` 上传新人物图 → 修改提示词中的场景或动作说明 → 运行。

**注意：** 这是换整个人，参考图里的脸、发型和衣服都会影响结果。只想换脸，选下一项。

提示词中的 `body_swap:` 是人物替换任务的标记，初次保留它。也保留 `<Video 1>` 与 `<Picture 1>`，它们告诉模型动作看视频、人物外观看图片。先选无遮挡、慢动作、单人的素材；多人、手挡脸或快速转身会更难。生成后动作和背景可能有变化，不等于原视频一模一样。

## 6. 视频换头（h3-head-swap）

**做什么：** 尽量保留原视频的身体动作和衣服，把脸与发型换成参考人物的样子。

**准备：** 一段单人短视频，加一张**主要包含脸、头发和少量肩膀**的参考图。

**怎么用：** 打开模板 → 上传原视频和脸部图 → 保留提示词里的 `head_swap:`、`<Video 1>` 和 `<Picture 1>` → 运行。

**注意：** 不要先拿全身照做换头参考。测试时全身参考图会把服装也带过去，所以先裁成头部图更合适。脸尽量清楚，角度与视频人物接近。

这个模板用换头 **LoRA**，也就是**给主模型补充某种能力的一份较小参数文件**。这里可以把它理解成换头用的补充文件。对应 `LoraLoaderModelOnly` 方框的 `strength_model` 默认 `0.8`；提高强度不一定更像，也可能改坏原画面，先保留默认。

重点检查侧脸、眨眼、头发边缘，以及有没有意外改变衣服。换头没有经过所有素材的稳定性验证。

## 7. 真人转动漫（h3-anime）

**做什么：** 把原视频重新画成动漫风格，尽量保留原动作和镜头位置。

**准备：** 原视频，加一张人物参考图。可以先用原视频中清楚的人物截图；想尝试指定动漫人物，也可以换成相应参考图。

**怎么用：** 打开模板 → 上传视频和图片 → 在提示词描述画风，比如干净线条、平面色块、手绘风格 → 运行。

**注意：** 动漫 LoRA 是负责补充动漫画风的较小参数文件，强度默认 `0.8`。这是重新生成画面，不是只在视频上加一层滤镜；脸、背景和动作细节都可能变化。原视频动作越简单、人物越清楚，越容易判断效果。

## 8. 稳定身体动作（h3-motion）

**做什么：** 从人物图生成动作视频，尝试让转头、站姿等身体动作更自然。

**准备：** 一张人物图，最好能看清你要动的部位。例如想看上半身动作，图片就别只留一张大脸。

**怎么用：** 打开模板 → 上传图片 → 描述一个简单动作，比如缓慢转头后站稳 → 保留提示词里的 `mvmt` → 运行。

**注意：** `mvmt` 是这个动作方案的提示标记。它不是上传一个动作视频、让人物照着演的模板；想模仿指定视频，用人物替换或边缘动作控制。

名字里的“稳定”是目标，不是保证。要比较它是否有帮助，尽量使用同一张图、同一段动作描述和同一个随机种子，观察肩膀、手、脖子是否变形，以及动作是否抖动。

## 9. 视频细节增强（h3-sharpen）

**做什么：** 参考已有视频，重新绘制一些细节，让画面看起来更清楚。

**准备：** 原视频，加一张清楚的人物参考图。尽量用同一个人物的图。

**怎么用：** 打开模板 → 上传视频和参考图 → 先保留提示词和参数 → 运行后，与原视频并排比较脸、衣服和背景。

**注意：** 当前模板不会自动把宽高翻倍，而且可能缩放到模板设置的尺寸。它也不是普通锐化工具；生成出来的细节可能是模型重新画的，不能当作找回了真实细节。

负责增强的 LoRA 文件名中带 `lms`，强度默认 `0.4`；`BasicScheduler` 方框里的 `denoise` 默认 `0.15`，也就是较小的重画幅度。如果发现变脸或衣服纹理变样，先尝试降低重画幅度。想得到更大尺寸的视频，看下一项。

## 10. 潜空间放大与二次采样（h3-latent-upscale）

**做什么：** 先从图片生成一段小视频，再把生成过程中的中间数据放大，并重新补一轮细节，输出更大尺寸的视频。

**准备：** 一张图。**当前模板的入口是图片，不是已有 MP4。**

**怎么用：** 打开模板 → 上传图片 → 描述动作 → 先用默认参数运行。默认第一阶段 512×320，最后输出 768×480。

**术语解释：** “潜空间”指模型使用的、经过压缩的画面中间表示；你不需要查看这份数据。“二次采样”就是在放大后，再让模型进行一轮生成来补细节。

**注意：** 这项比只生成小视频多了一轮处理，会花更多时间和内存。大图也不一定更好看，先确认小视频中的脸和动作没有明显问题。

如果要改最终尺寸，找 `MinimaxH3LatentUpscaler3D` 方框的目标宽高，同时修改第二个 H3 生成方框的宽高，让两处一致。第一次不建议动这些。原下载包的 RTX 超分工具没有适配当前 DGX 的版本，这里用的是另一个放大方案，结果不会与原工具完全相同。

## 11. 跟踪修脸与表情保留（h3-face-refine）

**做什么：** 找到原视频里的人脸，连续跟着脸的位置裁出小画面，重画脸部，再放回原视频。

**准备：** 一段脸部不够清楚的视频，加一张同一人物的清楚参考图。第一次只选一个主要人物。

**怎么用：** 打开模板 → 上传原视频和人物图 → 保持默认检测与修脸参数 → 运行 → 重点看眼睛、嘴巴和脸部边缘。

**注意：** 跟踪就是**连续几张画面里找到同一张脸的位置**。表情保留是目标，重画后表情仍可能改变。默认主要处理脸，不是修整个身体。

默认脸部处理画面是 512×512，重画幅度 `denoise` 为 `0.4`。若修完变得不像本人，先尝试降低这个值。`H3FaceStitch` 中的 `blend` 表示新脸与原脸混合的比例，默认 `1.0`，降低会多保留原画面；`feather` 表示把贴回去的边缘过渡弄柔和，避免明显的硬边。

特别小的脸、被挡住的脸、多人交叉出现，都更难修。看成片时检查有没有修错人、脸部闪烁、皮肤颜色不一致。这个模板接回的是原视频音轨。

## 12. Union 2.0 边缘动作控制（h3-union-control）

**做什么：** 先把原视频变成轮廓线，再让新视频参考这些线的位置，尽量跟住原来的构图和动作。

**准备：** 一段原视频，加一张你想生成的人物或画面的参考图。

**怎么用：** 打开模板 → 上传视频和参考图 → 修改动作与画面描述 → 先保持控制强度默认值运行。

**术语解释：** Union 2.0 是这套控制模型的名称。`Canny` 是找画面轮廓线的方法，例如找出人、衣服和桌子的边线。你上传正常视频，模板自动提取这些线，不需要自己画。

**注意：** 控制强度 `strength` 默认 `0.8`，在 `MiniMaxH3FunControlNetApply` 方框里。强度高通常更受原视频轮廓约束，但不一定更自然，也不一定更像参考人物。

当前配好的是**轮廓线控制**，不是精确的骨架动作捕捉，也不是直接读取人体关节。想改为姿态或深度控制，需要另配前处理；姿态图指身体关节位置图，深度图指物体远近的图，不能把一个选项随便换过去就认为已配好。

## 13. 子弹时间特效（h3-effects）

**做什么：** 尝试让人物动作几乎停住，同时镜头缓慢绕着人物转，类似电影中的慢动作环绕镜头。

**准备：** 一张主体清楚的图。

**怎么用：** 打开模板 → 上传图片 → 保留提示词开头的 `embedding:minimaxh3_bullet_time` → 在后面描述人物近乎静止、镜头缓慢环绕 → 运行。

**术语解释：** embedding 在这里是一份**帮助模型理解某种特效的提示数据**。那串文字是在调用它，不是需要上传的图片，也不是网址。

**注意：** 只写“子弹时间”不一定出现你想要的效果，同时描述动作速度和镜头方向更容易判断目标。当前已经实际生成过子弹时间样片，但不保证每张图都会明显触发。

还可以替换成下面的名字尝试其他方向。**下面九种已具备文件，尚未逐种验证效果**；换名字时也要把后面的画面描述改成对应效果。

| 提示词中的完整名字 | 可以尝试的画面 |
|---|---|
| `embedding:minimaxh3_spiral_ascent` | 镜头一边旋转一边升高 |
| `embedding:minimaxh3_four_seasons` | 同一个场景出现季节变化 |
| `embedding:minimaxh3_blooming_flowers` | 花朵逐渐开放 |
| `embedding:minimaxh3_fire_breath` | 奇幻喷火 |
| `embedding:minimaxh3_storm_magic` | 风暴魔法效果 |
| `embedding:minimaxh3_dark_magic` | 暗色魔法效果 |
| `embedding:minimaxh3_art_is_explosion` | 风格化爆炸 |
| `embedding:minimaxh3_kiss_camera` | 人物靠近镜头的动作 |
| `embedding:minimaxh3_truman_show` | 特定场景与镜头风格，需要试效果 |

## 14. 可复用人物参考素材（h3-refmod）

**做什么：** 把一张人物图处理成一份可以继续使用的参考文件，同时生成一条测试视频。

**准备：** 一张清楚的人物图。优先选脸、头发和服装都符合你后续要求的图片。

**怎么用：** 打开模板 → 上传人物图 → 运行 → 等作品库显示结果已保存 → 点击这条作品的 **查看全部结果** → 下载其中的 `.safetensors` 文件。下一项要用这份文件。

**术语解释：** RefMod 是这套人物参考保存功能的名称。`.safetensors` 是保存模型参数或参考数据的文件格式；**这里生成的是参考数据，不能因为后缀一样，就把它当作新训练的模型。**

**注意：** 当前方法把图片转成模型可以读取的参考数据，没有训练一个新的人物 LoRA，也不能保证以后怎么拍都不变脸。它主要方便保存和复用这张图提供的信息。

`ref_resolution` 是提取参考时使用的图片尺寸，默认短边 `256`。短边指图片宽高里较小的那个数；太低可能损失细节，提高会增加处理量，先用默认即可。视频和参考文件都会归档到本机，要保存的是本次任务输出的参考文件，不是模型下拉列表里的其他权重。

## 15. 载入已保存的人物参考（h3-refmod-reuse）

**做什么：** 用上一项保存的人物参考文件生成新视频，不需要再把原图片处理一次。

**准备：** 从“可复用人物参考素材”的任务结果里下载的 `.safetensors` 文件。

**怎么用：** 打开模板 → 找 `AIGCLoadH3Reference` 方框 → 点击 **上传参考素材** → 选择文件，并确认 `reference` 字段变成这份文件 → 修改 `prompt` 描述新动作 → 运行。

**注意：** 不要上传 H3 主模型、换头 LoRA 等其他同后缀文件。这里要的是上一项导出的参考文件。

`strength` 默认 `1.0`，表示按原有力度使用参考；降低会减弱参考对结果的影响。当前上传框允许的范围是 0～1。重新连接服务器后，需要重新上传参考文件；本机保存的文件仍可以继续使用。

如果参考文件是从低清图片提取的，复用不会凭空增加它没有的脸部细节。先比较新视频是否保持了你想要的人物外观。

## 工作台最前面的两个基础模板

### 首帧生成视频（h3-image）

一张图 → 从这张图开始生成视频。上传图片，描述后续怎么动，再运行。例如从房间照片开始，让镜头慢慢向前移动。

它是基础方案；上面第 1 项 LightX2V 首帧视频则配了另一套加速附加文件与参数。两者都可以让图片动起来。初次比较时，尽量用同一张图、同一段描述和相近的尺寸，不要直接混用两套方案的步数或附加模型。

### 参考图生成视频（h3-reference）

一张图 → 参考图里的外观或场景，重新生成视频。上传图片，保留提示词中的 `<Picture 1>`，描述你想拍的动作，再运行。

它与首帧模板的区别是：图片主要作为参考，不要求视频开头一定按原图完整复刻。例如拿一张人物图，想让同一个人换个姿势拍一段，可以先用它。实际人物相似度仍要看结果。

## 几种实用的组合方法

**让自己写的台词变成说话视频：** 先录音，或用 VoxCPM2 把文字生成语音 → 保存音频 → 用“录音驱动数字人”，上传人物图和音频。

**换人后再修脸：** 用“动作迁移与人物替换”生成视频 → 从作品库下载视频 → 打开“跟踪修脸与表情保留”，上传这条视频和新人物的清楚图片。

**把人物做成可复用参考：** 用“可复用人物参考素材”导出文件 → 在本机保存 → 下次用“载入已保存的人物参考”上传这份文件，换动作描述继续生成。

**做更大尺寸的视频：** 先用普通首帧模板检查动作方向 → 再用“潜空间放大与二次采样”上传同一张图、采用相同描述，生成更大版本。当前放大模板会重新生成一条视频，不会直接放大刚才下载的 MP4。

这些组合目前要手动下载上一阶段的结果，再上传到下一阶段；不是点一次按钮就自动完成整条链。

## 常见问题，用直白的话解释

**模板开了，但说找不到图片或视频。** 模板里只留了预设文件名。重新在对应上传框选择自己的文件，并检查框里显示的名字已经更新。

**服务器断开后，原来上传的素材不见了。** 上传素材放在临时会话里；会话结束时会清理。重新连接后重新上传。已经成功下载到本机作品库的成片和参考文件可以继续查看。

**人物视频很短，或长录音只用了前面一段。** 扩展模板默认约 5.17 秒；读视频的 `frame_load_cap` 表示最多读取多少帧，默认 124；数字人用 `max_frames` 限制最长画面张数。先把素材剪成约 3～5 秒再试。不要只提高一个地方的时长，就认为整套流程都已经同步改好。

**换了视频，人物动作还是与原来不同。** 换人、换头、动漫等模板是在参考素材的基础上重新生成，不是把原视频的每一张画面精确复制。单人、清楚、慢动作的素材更适合第一次试。

**成片声音与原视频不一样。** 换人、换头、动漫、细节增强、边缘控制等模板可能重新生成声音，不能默认它们保留了原声。想保留原视频的音乐或对白，可以生成后用剪辑工具替换音轨；音轨就是视频里的声音部分。修脸模板接原视频音轨，数字人模板接相应输入录音，提取人声模板接分离后的人声。

**想让人物说另一句话，改了提示词却没变。** 数字人的台词由上传的录音决定，先换录音。其他生成声音的模板也不能保证只靠文字得到准确台词。

**生成成功，但脸不像、手变形或者接缝明显。** 生成成功表示文件产出了，不表示画面质量过关。先简化动作、换更清楚的参考图，再固定随机种子，一次只改一个参数，比较结果。

**看到了红色方框、缺节点或模型不存在。** 节点就是负责某一步的小工具，模型文件就是它要用的生成参数。先确认打开的是 H3 环境并已就绪，再从工作台重新一键打开模板。若仍报错，保留错误文字；不要随便把下拉框里的模型换成同名或同后缀文件。

**作品已经保存，现在能断开服务器吗？** 确认工作台没有正在执行或归档的任务后，可以断开。归档就是把视频、工作流和相关结果下载并整理到本机；等显示已保存再断开更容易确认文件都拿到了。

## 画布里其他术语，看到时怎么理解

| 名称 | 直白解释 |
|---|---|
| 工作流 | 一套已经连好的操作步骤，例如上传图片 → 生成 → 保存 |
| 模板 | 已配好的工作流起点，打开后换成自己的素材即可试 |
| 模型 / 权重 | 模型学好的参数文件，用来生成或处理内容；这里已经配好需要的文件 |
| LoRA | 给主模型补充某种能力的较小参数文件，例如换头、动漫或加速 |
| VAE | 把画面或声音转换成模型用的压缩表示，并在最后还原成画面或声音的组件；第一次不必改 |
| 文本编码器 / CLIPLoader | 把提示词变成模型可以处理的数据；这里的加载方框已配好 |
| 采样 / Sampler | 模型一步步生成画面的过程或负责该过程的工具 |
| 潜变量 / latent | 生成过程中的压缩中间数据，还不是能直接播放的视频 |
| 遮罩 / mask | 用来告诉流程哪一部分需要改、哪一部分要尽量保留的范围信息 |
| 运镜 | 镜头如何移动，例如推进、跟拍或绕人物转 |
| 对齐 | 为符合模型要求，把尺寸或时长调整到支持的数值 |
| 校验 | 检查下载文件是否完整，避免只有半个文件却以为已经保存成功 |
